# Known limitations

- **New Qoder app:** correct target is desktop app 0.4.4. Its shared settings/SDK hook interfaces were inspected, but live delivery of all twelve events has not been exercised inside an authenticated task. NEXIS does not invoke paid agent tasks for verification. Shared `.qoder` settings cannot reliably distinguish desktop-app events from IDE/CLI events when those products run together. Health explicitly distinguishes configured and observed.
- Claude integration is fixture/transport tested against its documented schema; an interactive real Claude session and permission prompt still require user verification after opt-in hook installation.
- Desktop notifications require KDE's `org.kde.NotificationManager` watcher interface. NEXIS mirrors notifications; Plasma remains the daemon and may still show its own popup. DND suppresses island banners, and an unavailable DND state fails closed. The bridge keeps at most 20 plain-text notifications in memory, with five-second capsule previews; it does not import older Plasma history. Local dismissal removes only the island copy. No arbitrary browser download tracking or KDE job bridge is claimed; local jobs can publish progress using `nexis job`.
- No focus-app or open-project action: mappings from a hook session to a desktop window/project directory are not proven. Absolute project directories are intentionally discarded.
- No advanced CPU/temperature/RAM widgets; no process-based liveness inference. Unfinished sessions become stale after 15 minutes. Long, silent tool calls may therefore be marked stale until the next event.
- History is bounded and memory-only. No seven-day persistence or resumed sessions is claimed; restart starts with no sessions. History clear does not remove current session/job cards.
- Events lacking provider timestamps are ordered by receipt. Missing provider session IDs produce a workspace-scoped provisional identity with limited confidence; two such sessions may coalesce.
- Fullscreen observer handshake was verified on KWin 6.7.5. Hiding/restoring around a real fullscreen application, physical monitor hotplug, mixed-scale displays, window focus behavior during user workloads, and screen-reader output still require manual desktop acceptance. If the observer is unavailable, diagnostics report it; fallback Qt windows cannot guarantee Wayland placement.
- Active-display selection is resolved at placement updates using cursor location; it does not poll the cursor continuously or follow the active application across monitors. Selected displays retain their saved offsets and fall back if absent.
- Fold uses a consistent compact palette, honors dark/light and desktop brightness, and keeps the desktop font. Exact Orchis blur/shadow compositor effects are not reproduced. Artwork is local raster only; remote media art is omitted by design. Missing or expired artwork falls back to a music symbol. The pulse indicates playback state and is not an audio beat meter.
- Media controls and restart handling are verified with two isolated MPRIS providers. Actual Spotify/browser compatibility depends on those applications publishing MPRIS services. Position is refreshed while expanded, not while collapsed.
- Qt6 LayerShellQt 6.7+ enables anchored Wayland behavior. Ubuntu 24.04's default LayerShellQt package is Qt5; use a compatible Plasma 6 environment or accept regular-window fallback. Ubuntu 24.04 was not used as a test host.
- The notch overlaps the top panel using the overlay layer, a zero top margin and exclusive zone -1. A regular-window fallback cannot guarantee the same stacking/placement. The notch stays attached to the top edge; dragging and the old vertical-offset control are intentionally unavailable in this mode.
- Hook I/O deadlines are bounded, but kernel scheduling/startup are not real-time guarantees. Installer locks protect against other NEXIS writers; a different application ignoring locks can still race the final atomic replace.
- The ten-minute native baseline measured 0.06% CPU and 177.25 MiB mean / 198.61 MiB peak RSS; the 120 MB memory goal is not met. This baseline preceded final review fixes and the layer-shell initialization fix and measured the combined native process. Animation FPS, actual event-to-render p95, accessibility audit, and GPU memory remain unmeasured unless separately recorded in VERIFICATION.md.

- When permission/tool IDs are absent, correlation is conservative: anonymous permission attention may remain until a matching anonymous event, explicit turn/session transition or stale reconciliation.
